# Deterministic Authenticated Voice E2E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add deterministic Playwright coverage proving authenticated web voice generation reaches either playable audio or a terminal readable fallback through the real Next.js app and an isolated Neon branch.

**Architecture:** A fail-closed E2E identity resolver signs one test cookie and is active only in development on an ephemeral E2E branch. A local HTTP service emulates ElevenLabs and the private voice object store; production defaults remain unchanged, while the existing in-process development worker persists and completes the real voice job. Playwright observes UI transitions and queries the ephemeral database for durable evidence.

**Tech Stack:** TypeScript, Next.js 16 App Router, Clerk boundary, Prisma/PostgreSQL on Neon, Vitest, Playwright, Bun, Node HTTP server.

## Global Constraints

- Do not call live Clerk, ElevenLabs, Vercel Blob, or QStash from the default E2E suite.
- Activate test authentication and test storage only when `NODE_ENV=development`, `E2E_EPHEMERAL_BRANCH_ID` starts with `br-`, and the per-run secret is present.
- Preserve production voice eligibility, cadence, retry, queue, and retention behavior.
- Keep the existing guest E2E scenarios unchanged and continue running desktop and mobile Chromium.
- Use `bun run` and `bunx`; use Biome formatting and the existing logger rather than new production `console.log` calls.
- Write the failing test and observe the expected failure before each implementation change.
- Do not commit secrets, generated Playwright output, database URLs, or run-local audio objects.
