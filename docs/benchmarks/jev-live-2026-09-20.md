# Jev live evaluation, 20 September 2026

Keep the new memory review and retrieval decisions off globally. Live testing found a candidate-addressing bug, now fixed, plus remaining classification and confidence problems. The offline answer checker is useful for review, but its flags are not reliable enough to act on automatically.

## Scope and method

- Baseline: `7ab79cf7`. Real OpenRouter Decisions calls requested `typesafe/jev-1.13`; successful responses reported `typesafe/jev-1.13-20260917`.
- All examples were synthetic, with labels written before judging. No real-user conversations, live fact extraction, database writes, quota writes, or activation changes were involved.
- Memory and retrieval ran their actual core functions and production timeouts. Usage metering was replaced with a results collector. The answer checker used its existing offline evaluator.
- Model calls ran sequentially. Latencies include this workstation and network; this is neither a production load test nor a controlled speed comparison. Percentiles use nearest ranks.
- [Detailed results](runs/jev-live-2026-09-20.json) retain judgments, confidence, costs, synthetic request bodies, additional answer fixtures, diagnostics, and report-failure accounting. Expected labels were not sent to Jev.

### Memory bug and remaining failures

The original batch questions said `Review candidate 3`, but state contained an array without explicit candidate IDs. Outputs were consistent with confusing zero-based and one-based positions: a work retrospective was classified as equivalent to a guitar lesson, and a sister's sport was accepted for the account holder. A false equivalent match could discard a valid new memory.

The fix adds `candidate_N` IDs to state and names that exact ID in every review question. A request-only diagnostic corrected both associations. The full 11-case confirmation also rejected the wrong-person candidate and kept work separate from guitar. A new regression failed against the old source and passed with the fix. Confidence thresholds, consent rules, fallback behavior, and activation remained unchanged.

The baseline matched 13 of 19 candidate outcomes; the fixed run matched 15 of 19. Both runs matched 7 of 11 complete cases. The fixed run still missed one ordinary duplicate and two explicit corrections because of low confidence. A quoted fictional claim also passed through because Jev's `unsupported` judgment had low confidence and the existing fallback preserves the extracted candidate. These are unresolved limitations, not passing safety checks. The review was tested on supplied extracted candidates, so this does not measure the upstream extractor's error rate.

Before the confidence threshold, 80 of 92 raw choices matched the labels. All 21 uncertain statuses came from confidence below 0.8; Jev never selected the explicit `uncertain` choice. The threshold withheld 14 matching choices and 7 mismatches. Removing it would therefore release additional mistakes as well as correct judgments. These counts describe this synthetic corpus, not general model accuracy.

One of the 21 uncertain judgments was the expected outcome for missing context. The other missing-context example was flagged as an unsupported fact despite incomplete personal evidence. Quoted instruction examples also caused uncertainty.

The unaddressed-request disagreements concern the boundary between an explicit task, an implied request for help, and a correction. The declarative tennis example has no explicit task. The thesis-preparation intention and correction examples have more debatable labels. Preserve those disagreements rather than treating every one as an unequivocal model error or changing labels after seeing the result. These assistant-authored labels do not establish human preference, general coaching quality, or real-user value.

## Cost and failed reporting

There were 72 attempted live calls: 23 retained answer evaluations, 11 baseline memory cases, 11 retrieval cases, 11 fixed-memory confirmations, 4 diagnostics, and 12 answer calls whose results were lost by the temporary reporter.

OpenRouter reported **$0.004398912 across 58 calls**. **14 calls have unknown cost**: two timed-out planning calls and the 12 calls affected by the reporter failure. The reported amount is not the complete bill. No cost was assumed to be zero for an unknown call.

The temporary reporter passed the wrong label shape to `compareAnswerCheckLabels` after evaluating the additional 12 examples. It failed before saving their responses. The reporter was corrected to preserve each response before comparing labels, and the entire additional batch was repeated. Those original calls remain accounted for separately and do not contribute to the accuracy counts. No production evaluator code or fixture labels changed during this recovery.
